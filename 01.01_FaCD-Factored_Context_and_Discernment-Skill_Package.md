# FaCD Skill Prompt

## Task Framing

When this skill is active — meaning the Read Gate above has been satisfied — you write problems as semantic equations, factor both sides in public, open only the gates that do work, tag Phase III, and lead Clarity with the solution.

**Once activated, before producing a formal pass, read the teaching document in this package completely.** Then internalize the system and operate under it for the remainder of the relevant work.

### Activation Discipline (Binding)

The Read Gate is the first checkpoint; this section governs behavior once inside the package. Loading this package into context does not by itself mean operating under it.

- **Explicit invocation** ("use FaCD," "run a pass," "set this up formally," or the skill name): ask two short things if they are not already obvious — what the demand is (the one Right), and quick pass versus full rigor. Do not present a menu of pairings or techniques. Recommend light or full from the stakes you hear.
- **Ambient / brainstorming:** no ceremony. Lunch does not get `Left = Right`. A half-formed idea that is clearly "will this hold" may be thought through in FaCD form without phase headers until the structure would help rather than decorate.
- **No memorized command list for the user.** Pairings and techniques are the solver's vocabulary, not something the user is expected to name. After a pass you may name what you ran ("conflict balance, both camps failed alone").

Do not invent symbols. Combinations must stay intuitive; if not, `// comment //`. Keyboard-friendly operators only outside M. Miss is `!=`. Colon starts an expression, not a Subject, and is not fused to H or M. Nested H is `H(...)`. H starting an expression is `H:(...)`. Nested M is `M(...)`. M starting an expression may look like `M:E = mc^2` by placement only.

## When to Use

Use FaCD when a later reader must see why a claim, plan, or option meets or misses one demand. Especially: testimony versus record, stacked options versus constraints, a missing transform (lambda), staged goals, synthesis from hits and misses, hybrid math plus semantics, inherited machines, and imported domain knowledge that must be tested, not trusted.

## When Not to Use

Do not force a formal pass when the exchange is small talk, a lookup, or a one-line fact with no test. Do not turn a title into an equation. Do not let one tag bless two jobs.

If the work later becomes a real test, ask once whether to run FaCD.

## Core Directives (Binding)

1. Read the teaching document completely before a formal pass. Full read — no skim, regardless of length or perceived redundancy.
2. The Hard Rules of the Language Core are non-negotiable.
3. One Right per equation. Split when two demands cannot share one tag.
4. Stack options that share that Right when Synthesis may need factors from misses.
5. Phase I is level 0. Factoring is definitional reduction, not true inflation. Comments that will be used to solve must be marked and checkable (O8).
6. Shotgun only when level 0 already shows the sides meet. Shotgun does not feed Synthesis unless you then factor.
7. Working is gated. Tables are never required. Results enter Phase III unless `||...||` preserves the expression.
8. Phase III is the clean tagged equation. Clarity starts with the solution, then what it is, then why.
9. Synthesis keeps the same Right, builds a new Left from supporting factors — including misses — and reruns from Phrasing.
10. `(p:%)` only when verifiable. `(~p:%)` only when guessing, and it must show that it's a guess.
11. Curry with `::Name` or `"file"` plus a nested `'summary'`. Default reverse reads the in-line line, not the cache.
12. When in doubt, ask. Prefer the smaller pass that can carry an honest tag.

## Question Cadence

- On explicit invocation: demand and rigor, if not already obvious.
- After Phase III, if the tag is Unsolved or False and Synthesis or Inverse would change the work: name the gate and ask whether to run it.
- Before treating imported training, a comment, or a cross-loaded Semantic Shorthand log entry as evidence.
- When resuming a pass from a cached `::vN` or a hand-off from another session or agent: briefly confirm the current tag and the most recent Left before extending it, rather than assuming the cache is still current.
- Do not interrupt flow with a pairing menu.

## Success Criteria

A later reader can rerun the page: raw set, equation, factors, bridges, Working comments if any, tag, and a Clarity sentence that names the result without hiding a second job.

FaCD 01.01 — Module 0: Need, philosophy, axioms

Section 1. Need

What is true, how do we know, what responsibility do we have to it, and why does it matter? People decide with incomplete language, mixed perspectives, and bias that does not announce itself. Words stand in for states. Two factorings of the same word can look like a fight about the world when they are only a fight about the word.

Natural language hides its factors. A claim can look finished while its words are still closed. Strategy can look like one goal while it is two.

FaCD — Factored Context and Discernment — exists to write those sentences as equations so a tagged line can be checked. It puts a claim into a shared Language Core, writes it as `Left = Right`, factors both sides in public, names the links that must interact, and shows whether the sides meet or why they do not.

The Language Core is Semantic Shorthand 01.01. This guide teaches that language so FaCD can be used alone. The shorthand skill document remains the companion for logs, curation, and inheritance.

Purpose: make a problem readable as an equation; make the work that tests that equation rerunnable by someone who was not there; keep bridging and synthesis as visible moves instead of silent leaps.

Section 2. Name

- Factored: words are factored (opened). The factoring is the definition, not extra story.
- Context: the raw set plus only what a comment is allowed to add.
- Discernment: the tag on Balancing and the first sentence of Clarity.

It is not a memory system. External files and Special Sets are references, not a hidden store.

Section 3. Philosophy

FaCD is not a new mind. It is a way of writing what a mind already does, so the doing can be checked.

At a first, often unnoticed pass, a person organizes a situation (phrasing), identifies what the words already mean from experience (factoring), flags clash and support, and sometimes links two things into a third (bridging). Directed FaCD makes the same sequence visible: the equation is written; the factors are listed; the links are declared; the tagged line is tested; the result is said so another person can point at a line instead of a mood.

A state is the condition itself. A sentence is not the state. A definition equals a term when the factoring is actually equivalent — the dictionary case. That equality does not make the definition equal to the thing. Factoring approximates our hold on the state by factoring the words we used. It does not finish the state.

A perspective is the set of expressions available from one point of reference — person, instrument, or object-state — about a condition. One perspective is limited by what it has seen, what it can name, and what emotion or habit is steering recall. Adding non-contradictory perspectives usually improves the approximation. It does not complete it.

Bridging is core. Two or more factors can become the definition of a new term, or become an emergent thing that did not sit inside any one factor. Bridges can be bridged. Synthesis is the same family of move used on whole left-hand sides when the first tagged line misses: stack what survived, form a new Left, keep the same Right, run the flow again.

The method follows algebraic discipline on purpose. A claimed equivalence is written. Operations happen to both sides. Silent extras do not enter Phrasing. New words in Factoring are the term factored, or they are a declared bridge, or they are a comment still marked as extra. If misunderstanding survives Balancing, the page still shows the factor, the bridge, or the setup where it happened. That is how experiential and emotional bias gets reduced or at least exposed.

More independent perspectives, factored and balanced, usually tighten the approximation. That is said without a formula. There is a pass you can read.

`2 + 2 = 4` is the picture: one side is offered as the same as the other. Semantic equations use that picture on words.

Section 4. Axiom 1 — Truth is a perspective approximation

The full condition of a state is larger than any one perspective’s expressions about it. What we can write is a perspective-truth: the non-contradictory expressions that perspective can currently hold.

Supporting statements

- Language is the medium of that write-up. A change of factoring can change the written truth without the state moving.
- Non-contradictory further perspectives, factored and balanced with what is already on the page, usually improve the approximation.
- Improvement is not completion. An approximation remains an approximation at every depth we actually run.
- A definition may equal a term. It does not equal the state.

Section 5. Axiom 2 — Validity is verified by equivalent balancing

A claim is tested by writing it as `Left = Right` (or showing `!=`), factoring both sides, removing contradictions, and adding only what those factors or declared bridges require. If the sides then say the same thing, the claim holds in this language, at this depth, for these perspectives. If they cannot, the claim is False, the plan is Unsolved, or the pass is Unknown and may gate to Synthesis.

Supporting statements

- Validation is the flow of operations, not a feeling of certainty.
- Both sides are factored. One-sided factoring is an incomplete test.
- Working instruments feed Balancing; they do not replace it.
- `(p:%)` and `(~p:%)` never stand in for a missing factoring.
- A later reader must be able to rerun the flow from the page. If they cannot, Axiom 2 was not met.

Section 6. Recommendation — Transparency and sharing

Write so another person can rerun the flow. Share factors, bridges, tags, and Clarity. A singular perspective is limited by exposure and by the emotions that steer recall. Sharing is how that limit gets checked. This is practice under Axiom 2, not a third axiom.

Section 7. Conjecture — There are no semantic primes

Every term factors into other terms. Words are defined by other words. No word can define itself as a last unfactorable atom.

Supporting statements

- All semantic identifiers are defined by other semantic identifiers.
- There is therefore no bottom word that ends factoring.
- Recursion, overlapping definitions, context drift, and honest misunderstanding follow from that single claim.
- The method exists because words do not finish. The honest test is to show the factors.

The conjecture is a claim about language, not a rule of write.

Section 8. What this system will not do

- It will not turn a title into an equation.
- It will not let one tag bless two jobs.
- It will not treat a research tagged line as a world-proof.
- It will not require a table, a matrix, or a tensor glyph.
- It will not package logs or inheritance. That is the shorthand companion.
- It will not settle a question by a letter-legend compression layer.

Section 9. Contents of this guide

- Module 0 — Need, philosophy, axioms
- Module 1 — Language: read/write, Hard Rules, Soft Rules, symbols
- Module 2 — Core concepts and foundational skills
- Module 3 — Flow of operations
- Module 4 — Rosetta (raw to phrase to reverse)

FaCD 01.01 — Module 1: Language

Section 1. What this module is

Every FaCD line is Semantic Shorthand. This module teaches that language completely enough to read, write, and reverse-translate without the companion file open. The companion remains the reference for logs, curation, and inheritance.

Sacred content, always kept: subjects, attributes, interactions, decisions, reasoning, relationships, conditionals, dependencies, outcomes.

Filler only: articles and connective tissue a fluent reverse can supply. Filler is never an excuse to drop sacred content.

Section 2. Readable Flow

Write left to right so the line already sounds like the thought. The reader must not reorder the parts to recover meaning.

There is no left-pointing flow arrow. Reverse causation is a new phrasing, a comment, or a nested reason.

Section 3. Expression syntax

Minimum: `:Subject`  
Typical: `:Subject, attribute (modifier (sub-modifier))`

The Subject is the word immediately after the colon (after any prefix such as `?` or `M`). Capitalization is style. Proper nouns keep their casing (`:iPhone`).

- An attribute is a quality or descriptor of the Subject.
- A modifier is an attribute of an attribute.
- A sub-modifier is an attribute of a modifier, or a standard slot on the expression: time `(t:...)`, space as dimension or layer `(d:...)` and coordinates `(co:...)`, probability as a verifiable rate `(p:%)` or as a guess or confidence `(~p:%)`.

Each of those is a factor of the expression’s context. Expressions themselves are factors of a perspective’s context.

Attributes that are separate facts use commas. Modifiers nest in parentheses on the attribute they modify. Sub-modifiers nest inside modifiers, or sit in their own parenthetical slot when they belong to the whole expression rather than to one modifier.

A FaCD problem adds one requirement: the offered line is a semantic equation `Left = Right`. An optional title `:Name (?)` is not the equation.

Readable Flow on a finished expression:

```
:Vendor, good (Delta), reason (technical + pricing + Q4) -> Contract >> legal review
```

Reverse: The vendor looks good to Delta for technical, pricing, and Q4 reasons, then a contract, which requires legal review.

The parts already stand in speaking order. No reordering is required to recover the thought.

Section 4. Nesting

Nesting is depth. An expression, a modifier, a comment, or a set may sit inside another.

- A modifier belongs to the word it sits on. A sub-modifier belongs to that modifier, or to the expression when it is a standard slot.
- `( )` is belongs-to as well as innermost grouping.
- When a word is factored later in the flow, it becomes a new Subject and its factors nest under it.
- A nested comment is still added context. It may be factored only when the flow allows a checkable comment.
- Stages nest under `H` or `+`. A Special Set nests its body in `::Name:(...)`.

Do not flatten a nested clause into a second Right.

Section 5. Hard Rules

H1. Correct syntax, left to right.  
H2. Sacred content preserved for reverse translation.  
H3. Nested comments are the only inflation.  
H4. The in-line expression is the live line. A replaced in-line lives in `// ... ::vN //`.  
H5. Spaced `-` means remove or subtract. Attached `-x` is a negative number inside M only. Semantic negation is `!` only.  
H6. `^n` attaches only to `)`, `]`, `}`, or `::Name`. Bare `mc^2` is exponentiation and lives in M.

Section 6. Soft Rules

S1. Prefer stacking on one readable line.  
S2. Prefer nesting under the related expression when the line would break.  
S3. Standard compression is the default. Looser or denser only when needed. `||...||` never flexes.  
S4. Sub-modifiers only when they add precision.  
S5. `(p:%)` only when a verifiable rate matters later.  
S6. Combined symbols must stay intuitive. If not, `// comment //`.  
S7. Create `::Name` when grouping is requested or reuse is agreed.  
S8. Capitalize Subjects as style, not as a parse rule.  
S9. Prefer `1, ..., 4` for ranges in notation. The word `through` is only for reverse translation. Do not attach `1-4`. Reserve `Hn` for progressions whose endpoint is ugly to write.

Section 7. Prefixes

`: ` Starts an expression, not a Subject by itself. The word after the colon is the Subject of that expression.

```
:Project, status (active)
```

Reverse: The project's status is active.

When `H` starts the expression, write `H:(...)`. The colon after `H` is the same prefix: a new expression begins. Inside that expression, `1:Sally` is not a second expression. The number is the correlator; the colon after the number keeps the number off the Subject name so `1` is not read as part of Sally.

```
H:(1:Sally, 2:Mark) -> store, buy (1:shoes, 2:hat)
```

Reverse: Sally and Mark go to the store; Sally buys shoes and Mark buys a hat.

`?` Unknown or uncertain. Prefix, suffix, or modifier. Distinct from `~`.

```
?:Active
:State?
```

Reverse: Possibly active. / State, unconfirmed.

`~` Approximate. Known, not precise.

```
Delivery ~Friday
```

Reverse: Delivery around Friday.

`::Name` Special Set. A named reusable collection. The same Name in different places joins one set. Later `::Name` stands for the joined contents. Not the same as `::vN`.

```
::CoreTeam:(Alice + Bob + Cara)
```

Reverse: The Core Team is Alice, Bob, and Cara.

`M` Math mode prefix. Not fused to the expression colon. In that segment, symbols read as mathematics first. Algebra, calculus, matrices, tensors, and Greek letters are legal. Semantic words may label parts of an equation.

```
:Energy, M(E = mc^2)
```

Reverse: Energy equals m c squared.

Section 8. Logic symbols

`+` Join / AND. Combined relationship. Also the shared-subject join.

```
cereal + milk
```

Reverse: Cereal and milk.

`-` Remove / subtract. Always spaced.

```
Group - Mary
```

Reverse: Mary is removed from the Group.

`,` Loose succession. Listed order only. Weakest order. Stacking separator.

```
:Project, status (active), owner (Priya)
```

Reverse: The project's status is active, and its owner is Priya.

`Alice, Bob` is two facts. `Alice + Bob` is a join.

`|` OR.

```
A | B
```

Reverse: A or B.

`!` NOT / exclusion. The only semantic negation. May attach to any component.

```
!:Approved
```

Reverse: Not approved.

`!=` Not equal / does not meet.

```
:Plan != :Goal
```

Reverse: The plan does not meet the goal.

`<` `>` `=` Comparison or offered equivalence.

```
50 < 100
:Claim = :World
```

Reverse: 50 is less than 100. / The claim is offered as equal to the world-condition.

`<=` `>=` Inclusive comparison. Legal compounds.

`is` in speech is `=`. An attribute is not an equation. `:Door, locked` reverses to locked door. `:Door = :Locked` reverses to the door is locked.

Section 9. Flow symbols

`->` Then / sequence. Middle order strength. Also if-then when the left is a trigger.

```
Research -> Analysis
:Paid -> :Shipped
```

Reverse: Research, then Analysis. / If paid, then shipped.

`->>` Becomes.

```
design ->> prototype
```

Reverse: The design becomes a prototype.

`>>` Requires / depends on. Dependent first. Arrow toward the dependency. One direction only.

```
Approval >> Budget
```

Reverse: Approval requires Budget.

`><` Else. Form: `(If) -> (Then) >< (Else)`.

```
continue >< turn back
:File, exists -> :Open >< :Create
```

Reverse: Continue, else turn back. / If the file exists, open it; else create it.

`<->` If and only if.

```
Ready <-> Checks passed
```

Reverse: Ready if and only if checks have passed.

`;` Lambda. Unknown transform between two known ends: `Input ; Output`.

```
:Fuel ; :Drive
```

Reverse: Fuel transforms into Drive; the mechanism is not yet named.

Section 10. Grouping, order, loops

`( )` Innermost set. Nesting also means belongs-to.  
`[ ]` Intermediate set.  
`{ }` Outermost set.  
Use only the depth containment needs.

`||...||` Absolute / Invariant. Exact text, constants, locked constraints. Not inflation. Never paraphrased.

```
:Box, cost < ||$40||
```

Reverse: The box must cost less than exactly forty dollars.

`H` Hierarchy / order prefix. H is not fused to the expression-starting colon. If H prefixes the whole expression, the colon follows by placement: `H:(1: Research, 2: Design)`. If H sits inside an already-prefixed expression, write `H(...)` with no colon on H: `:Shipped, H(1: design, 2: test)`. `1:` before a name is only the correlator.

```
H:(1: Research, 2: Design, 3: Build)
H:(1:Sarah + 2:Bob + 3:Mike), hungry -> shop (1:shake, 2:burger, 3:fries)
```

Reverse: First research, then design, then build. / Sarah, Bob, and Mike are hungry, so they went to the shop; Sarah got a shake, Bob a burger, Mike fries.

`Hn(...)` Pattern calculated to n terms. Rare. Use when a bookend end-value is ugly to write. No prefix colon. `Hn` is not an expression and is not a Subject. A Subject begins an expression and is the minimal factor of that expression. A bare pattern with no surrounding expression has no context, so `Hn` only sits inside an expression that already has a prefix.

```
:Count, H10(2, 4, 6, ...)
```

Reverse: The count is 2, 4, 6, … to ten terms ending at 20.

`...` Pattern continues, or a range. Leading, mid-list, or trailing.

```
2, 4, ..., 10
1, ..., 4
```

Reverse: 2, 4, 6, 8, 10. / 1 through 4 inclusive. Not `1-4`.

`^n` Repeat the preceding grouped block n times from the start. Only on `)` `]` `}` or `::Name`.

```
(:Boy, baseball, hit -> run)^2
```

Reverse: He hits, then runs. Then the whole thing again.

`Hn` grows one progression to n terms. `^n` restarts a finished block. They are not interchangeable.

Section 11. Wraps and sub-modifiers

External reference and its summary nest together so the summary cannot be read as belonging to another clause:

```
"wind_box_tuesday.md"
'(context) Tuesday notes on the field box'
```

`"..." ` names the file or source only.  
`'...'` summarizes that same reference. Write the summary immediately under the name.

`//...//` Comment, instruction, or clarification. Added context.  
`::vN` Version suffix. Lives inside a comment only.

`(p:%)` Verifiable probability.  
`(~p:%)` Guess, confidence, or admitted bias.  
`(t:...)` Time or duration.  
`(d:...)` Dimension or layer.  
`(co:...)` Coordinates.

Any word or value may also nest as a sub-modifier. Sub-modifiers never stand as Subjects.

Tables, charts, matrices, tensors: write a header, a comment naming what the grid is, and the grid itself. M if the cells are math. `(d:...)` if axes are dimensions. No extra glyph.

Described media: still picture `(co:)` plus optional `(d:)`; frames add `(t:)`; audio is `"clip"` plus a nested `'summary'`, or M if calculated. Substitute only the conclusion.

Section 12. Shared subjects and correlated items

Default join: group the subjects, write the shared attribute or interaction once.

```
:(Subject1 + Subject2), hungry -> store
```

Reverse: Subject1 and Subject2 are hungry, so they go to the store.

Non-shared items, two legal forms. No extra glyph. Default to Form B when slots must stay paired.

Form A — nest each subject’s own clause inside the join when the extra is short:

```
:(Sally, buy (shoes) + Mark, buy (hat)) -> store
```

Reverse: Sally and Mark go to the store; Sally buys shoes and Mark buys a hat.

Form B — `H:` numbers correlate subjects to later slots. Use this when the pairing must stay obvious:

```
H:(1:Sarah + 2:Bob + 3:Mike), hungry -> shop (1:shake, 2:burger, 3:fries)
```

Reverse: Sarah, Bob, and Mike are hungry, so they go to the shop; Sarah gets a shake, Bob a burger, Mike fries.

Do not write `1*Sally` or `1*shoes` as a correlator. `*` multiplies inside M. It is not a subject label.

Section 13. Combining symbols

Any Core symbols may combine if the result stays left to right and obeys Hard Rules. If it is not obvious, add `// comment //`.

Examples of good compounds — a method, not a closed list:

```
?->      possibly then
->?      then, possibly
!->>     does not become
!+       NAND
!|       NOR
!<->     XOR
~->      roughly then
!=       does not meet
<=  >=   inclusive comparison
```

Common compound mistakes

| Written | Mistake | Why |
|---|---|---|
| `->>>` | three arrows | Does not read as “eventually.” Write `->>` and a comment if timing must be said. |
| `!-` | not-remove | Absence of `-` already means nothing was removed. |
| `1-4` | attached hyphen as range | Collides with remove/subtract. Write `1, ..., 4`. Reverse may say through. |
| `<-` | left arrow | No reverse-causation glyph. Rephrase, comment, or nest the reason. |
| `1*Sally` | star as a label | `*` multiplies inside M. Use `H:(1:Sally)` or Form A. |

Clarity

| Aim | Write | Reverse |
|---|---|---|
| Inclusive cap | `cost <= \|\|$40\|\|` | Cost is less than or equal to exactly forty dollars. |
| Does not meet | `:Plan != :Goal` | The plan does not meet the goal. |
| Exclusive branch | `:Exists -> :Open >< :Create` | If it exists, open; else create. |
| Named set reused | `::CoreTeam` after `::CoreTeam:(...)` | The Core Team, as already named. |

Section 14. Syntax checklist

1. Colon, then Subject.  
2. Readable Flow.  
3. Attribute of Subject, modifier of attribute, sub-modifier of modifier or standard slot.  
4. `::Name` joins by shared Name.  
5. Set depth only as needed.  
6. `H` for explicit order; `Hn` rare.  
7. M when math meaning must win.  
8. `||...||` for exact lock.  
9. Combine only while intuitive.  
10. Sub-modifiers live in parentheses.  
11. Stack by default.  
12. `...` for pattern or range.  
13. Reference and summary nest together.  
14. Left to right.  
15. `^n` only on a grouped close or `::Name`.

FaCD 01.01 — Module 2: Core concepts and foundational skills

These sections are operational templates later modules follow. Style may vary. The jobs do not.

Section 1. Language

The language is Semantic Shorthand 01.01. Module 1 taught how to write it. This module names the ideas the writing carries.

FaCD uses that same Core as a logic: lines are tested as equations. Logging practice lives in the companion. This guide can be used alone.

Section 2. Expression

Template:

```
:Subject, attribute (modifier (sub-modifier))
```

An expression is one colon-started unit that names a Subject and the factors that belong to it.

```
:Sky, color (blue (t:day)
```

Reverse: The sky’s color is blue during the day.

Minimum: `:Sky`.

`is` means equals. An attribute is not an equation.

```
:Door, locked
```

Reverse: Locked door.

```
:Door = :Locked
```

Reverse: The door is locked.

A perspective, an expression, a Subject, an attribute, a modifier, and a sub-modifier are all factors of context. They differ only in scale. Phrasing raw data into this syntax writes those factors at level 0. That is the Factored in Factored Context and Discernment.

Section 3. Perspective

A perspective is the set of expressions available from one point of reference — person, instrument, or object-state — about a condition.

```
:Alice, prefers (morning)
:Bob, prefers (afternoon)
```

Reverse: Alice’s preference is morning. Bob’s preference is afternoon.

One perspective is limited by what it has seen, what it can name, and what habit or emotion steers recall. Adding non-contradictory perspectives usually improves the approximation. It does not complete it.

A state is the condition itself. A sentence is not the state. A definition may equal a term. It does not equal the state.

Section 4. Phrasing

Phrasing is writing the raw set as expressions. Sacred content stays. Filler drops. Readable Flow holds. Those expressions are level-0 factors of context.

Show every slot of the expression template.

Raw: Dana filed the report early Monday from home.

```
:Dana, report (filed (early (t:Monday))), location (home)
```

Reverse: Dana’s report was filed early Monday from home.

Subject `:Dana`. Attribute `report`. Modifier `filed`. Sub-modifier `early` with standard slot `(t:Monday)`. Second attribute `location` with modifier `home`.

Phrasing is not yet a test. It becomes a test when the expressions are written as an equation.

Section 5. Semantic equation

A semantic equation applies the picture of `2 + 2 = 4` to words. One side is offered as defining, explaining, or satisfying the other.

```
:Plan, hire (two), start (Monday) = :Desk, covered (week)
```

Reverse: The plan to hire two people starting Monday is offered as covering the desk for the week.

Left is the offered account. Right is what that account must meet. Algebra writes an equivalence and operates on both sides. FaCD does the same.

A title `:Cafe (?)` is not an equation. `=` or `!=` is.

Open-ended form: `:Steam = ?` means the Right is not yet written. Factoring supplies it.

Section 6. Setup

A setup is how Left and Right are paired for a job. Any Left type may meet any Right type when the pairing is the actual job.

World and evidence may serve the same role. Plan and options may serve the same role. Other pairings exist and are taught with the setups.

Do not treat a list of family names as a closed law. Choose the pairing the raw set is doing. Mix pairings when the session actually mixes jobs — still one Right per equation unless a split is underway.

Section 7. Stacking

Stacking lists options or potentials as perspectives — stacked expressions — on one Left against one Right.

Loose list:

```
:Alice, prefers (morning), :Bob, prefers (afternoon), :Cara, prefers (evening) = :Shifts, covered
```

Grouped subjects, shared attribute. `prefers` is shared, so it needs no `H`:

```
:(Alice + Bob + Cara), prefers
:(Alice, Bob, Cara), prefers
```

Non-shared slots must stay paired. Correlators follow Module 1: `H:` starts the expression; `1:` before a name keeps the number off the Subject.

```
H:(1:Alice, 2:Bob, 3:Cara), prefers (1:morning, 2:afternoon, 3:evening) = :Shifts, covered
```

Reverse: Alice prefers morning, Bob afternoon, Cara evening, offered as covering the shifts.

A single option may be written alone. Stacking is the strong recommendation when a new option may need factors from misses as well as hits.

Section 8. One Right

The Left may stack many options. The Right is one demand on this equation.

Two demands are two equations. Split and link is taught with methods.

Section 9. Nesting

Nesting is belongs-to depth. Keep related context under the word it belongs to. Do not flatten a nested clause into a second Right.

Normal form — one Subject, nested modifiers:

```
:Car, speed (fast (super))
```

Reverse: The car’s speed is fast, specifically super-fast.

Default to dense when attributes are shared, even if some slots are not shared.

Dense:

```
H:(1:Sally, 2:Mark) -> store, buy (1:shoes, 2:hat)
```

Expanded (same facts):

```
H:(1:Sally, 2:Mark) -> store
H:(1:Sally, buy (shoes) + 2:Mark, buy (hat))
```

Reverse: Sally and Mark go to the store; Sally buys shoes and Mark buys a hat.

Dense is the default. Expanded is fine when clarity for quick review matters more than density, or for a novice reader.

There is no cap on how many modifiers or nested sub-modifiers a factor may carry. Depth follows need and Readable Flow.

Section 10. Sets — grouping and internal linking

`( )` `[ ]` `{ }` are the basic grouping form. Depth hierarchy is Module 1. A group may already sit in the raw set, or the writer may make one because context needs it (these three people are one team).

A Special Set is internal linking: group data, name it, reuse the name.

First write holds full content. That write is the reference point. Later write is the name only.

```
::CoreTeam:(Alice + Bob + Cara)
::CoreTeam
```

Reverse: The Core Team is Alice, Bob, and Cara. / The Core Team, as already named.

`::Name` is internal. It is not an external file.

Style follows need. Steam as **state** (no becoming):

```
::SteamDef:(Water, vapor, hot (>= ||100 C||))
```

Reverse: SteamDef is hot water-vapor at or above one hundred degrees C.

Steam as **interaction** — examples of legal styles, same job:

```
::SteamDef:(water ->> gas >> heat)
::SteamDef:(:Water + :Heat ->> :Gas)
::SteamDef:(:Water ->> :Gas >> :Heat)
```

Reverse: Water becomes gas and that requires heat. / Water plus heat becomes gas. / Water becomes gas, requiring heat.

Symbols may sit inside a set or expression. They are not only glue between whole expressions.

Do not hang `=` on the Special Set line. Name the set, or write an equation, or write both as two lines.

Section 11. Versioning and cache

The live in-line equation is what reverse translation must recover. Other tries sit nested in comments as a cache list.

```
:Steam = (:Water + :Heat) ->> :Gas
// ::v1 :Steam = hot vapor //
// ::v2 :Steam = mist //
```

Why: brainstorm and test without losing a try. When: the line changed and an old write may be needed. `::vN` lives inside a comment only.

Section 12. External references and summaries

External linking points to a file or source outside this page. The name uses full quotation. The summary nests immediately under it.

```
"wind_box_tuesday.md"
'(context) Tuesday notes on the field box'
```

Reverse: External file wind_box_tuesday.md; summary: Tuesday notes on the field box.

Internal linking uses `::Name`. External linking uses `"..."` plus nested `'...'`.

Section 13. Factor and factoring

A factor is a piece of context that belongs to a larger unit. Perspective, expression, Subject, attribute, modifier, and sub-modifier are all factors of context. Phrasing writes them at level 0.

Factoring is opening a level-0 factor. Opening is the same act. This guide uses factoring as the name.

Take that element and make it the new Subject. Its attributes are the descriptors of its definition. Each factor may have modifiers, several modifiers, sub-modifiers nested, or sub-modifiers standing alone.

Template:

```
:Term, factor (modifier (sub-modifier)), factor
```

`:Term` is the new Subject. What follows are the factors of that term.

Level 0:

```
:Latch, engaged
```

Reverse: Engaged latch.

Factor the word engaged (not the latch):

```
:Engaged, bolt (seated (full)), handle (turned)
```

Reverse: Engaged is a fully seated bolt and a turned handle.

Definitional reduction: more tokens, same meaning. True inflation is context the raw set did not give. It lives in a comment and is factored only when checkable.

Both sides of an equation are factored.

Section 14. Bridging

Bridging names a link or an emergent link or quality from two or more factors.

Keep the original phrase on the page. Factor. Then bridge those factors so the new line is equivalent to that original.

Original phrase:

```
:Door = :Secure
```

Reverse: The door is secure.

Factor each side:

```
:Door, latch (present)
:Secure, bolt (seated (full))
```

Bridge:

```
:Latch + :Bolt, seated -> :Engaged = :Secure
```

Read: latch plus a seated bolt yield engaged, which meets secure. That is what the original `:Door = :Secure` was claiming. Without the original line, the bridge has nothing to equal.

A bridge can become the definition of a new term. Bridges can be bridged.

Section 15. Working

Working is an instrument: math, table, matrix, tensor, flowchart, code block, described media. It is not factoring and not yet the balanced line. Use it when the sides cannot be seen to meet without it. Skip it when they can.

Results live in comments or as substituted numbers. The grid is not the tag.

Section 16. Balancing

Balancing is the clean equation after factoring and links. The sides are offered as equivalent, or shown not to be.

```
:Door, latch + :Bolt, seated = :Secure
```

Reverse: Door as latch plus seated bolt equals secure.

That line is the original `:Door = :Secure` after both sides were factored and bridged.

Section 17. Tag

A tag is the phase header: the phase name plus the success or truth label.

```
Balancing — Solved
Balancing — True
Balancing — False
Balancing — Unknown
Balancing — Unsolved
```

The tag is not a mood. It is whether the sides say the same thing at this depth for these perspectives.

Section 18. Clarity

Clarity is a stage of the flow. It states the solution first, then what it is, then why.

If Clarity cannot name the result in one sentence without hiding a second job, the write still has two jobs.

Section 19. Synthesis

Synthesis builds a new Left (option or strategy) from supporting factors and bridges — from successful options and from failed ones — so that Left better satisfies the Right (evidence, constraint, or goal). The Right stays the same. The old tagged line is cached. The flow runs again.

Steps

1. Phrase the equation from given data only.  
2. Factor both sides. Reasons not in the raw set live in comments first, then factor only if checkable.  
3. Tag the first balance.  
4. If it misses and a better Left is the point, collect supporting factors and bridges from hits and misses.  
5. Write the new Left. Keep the same Right. Cache the old line as `::vN`.  
6. Run the flow again.

Worked passes live with the later synthesis teaching.

Section 20. Currying

Currying (chaining) hands a finished result to the next equation as input. A connective by relationship or interaction must link them. The second line is not a silent restatement of the first.

```
::SteamDef:(:Water + :Heat ->> :Gas)
:Kettle + ::SteamDef -> :Kettle, steamed
```

Reverse: SteamDef is water plus heat becoming gas. The kettle plus that steam becomes a steamed kettle.

`::SteamDef` is carried in as a factor. `+` and `->` say how it meets the kettle. `:Kettle, steamed = ::SteamDef` would claim the kettle is the definition. That is the wrong link.

Ordered subgoals use `H`. Unordered use `+`.

Section 21. Lambda

Lambda marks a missing transform between two known ends. The symbol sits between those ends. Deeper solve is taught with methods.

Template

```
:Heat ; :Steam = ?
```

Reverse: Heat transforms into steam by an unnamed process.

A short derivation using the steam already on this page:

```
:Heat ; :Steam = ?
::SteamDef:(:Water + :Heat ->> :Gas)
:Heat + :Water ->> :Gas = :Steam
:Heat ; :Steam = :PhaseChange
```

Reverse: The hole between heat and steam is the phase change already named in SteamDef.

If an end is missing, the write is research or `-> ?`, not lambda.

Section 22. Mixing

Mixing is using more than one setup, technique, or method in one session. Each equation still has one Right and one tag.

Series: chain one pairing into another. Research `:Steam = ?`, then use that result as a side of `:Heat ; :Steam`, then use `::SteamDef` in a plan.

Parallel: run two equations at once and link them with a Special Set so both results feed a larger job. Split a large goal into smaller staged equations the same way.

Synergy: curry a result into a different move, or run two instruments on one equation.

Illegal: three Rights and one tag.

Section 23. Short map

| Idea | Template |
|---|---|
| Expression | `:Subject, attribute (modifier (sub-modifier))` |

| Version cache | live line + `// ::vN ... //` |

FaCD 01.01 — Module 3: Flow of operations

Module 1 is the language. Module 2 is the templates. This module is the pass: what to write, in what order, when to skip, and when to stop.

Section 1. The flow

```
Phase I: Phrasing                 // level-0 equation
 -> Phase II: Factoring           // the factored word is the new Subject
 -> Phase II?: Bridging           // gated
 -> Phase II?: Working            // gated
 -> Phase III: Balancing — <tag>
 -> Synthesis?                    // gated: miss, or hit and a stronger Left is the goal
      -> new Left, same Right, cache old line, return to I
 -> Phase IV: Clarity             // only when this pass is complete
```

Header convention. Work lives under the header. A note may sit before or after the work block.

```
Phase I: Phrasing
Phase II: Factoring
Phase II?: Bridging
Phase II?: Working
Phase III: Balancing — True | False | Unknown | Solved | Unsolved
Phase IV: Clarity
```

A pass is one trip from raw phrasing to a tagged line, then Clarity if that pass is complete. Synthesis starts another pass. Curry hands a finished result to the next equation.

Use a gated phase only when the next clean line cannot be written without it.

Section 2. Operational rules

O1. Phrasing is a semantic equation. One Right. A title is not the equation. Known numbers and formulas already in the raw set sit on Phase I as attributes, modifiers, or sub-modifiers.

O2. Both sides are factored when Factoring is used. Factoring is opening by reduction. The factored word becomes the new Subject. Phase I is level 0. Deeper levels are sections under Phase II.

O3. Bridging is gated. Use it when factors must be linked or an emergent link or quality must be named. Skip when factored sides already meet.

O4. Working is gated. Use it to solve math already on Phase I, or math revealed later by factoring, comments, or reasons. Also tables, matrices, arrays, logic tables, tensors, graphs, flowcharts, described media. Phase III shows the result unless `||...||` preserves the expression; a preserved expression may still carry `result (...)`. Skip when I–II already suffice. A table is never required.

O5. Phase III is only the clean balanced equation plus the phase header tag.

O6. Synthesis writes a new Left from supporting factors and bridges — hits and misses — and keeps the same Right. Both sides are factored again. Use it when Phase III cannot finish, or when Phase III already holds and a stronger Left is the goal. Stop when the new Left does not improve the tagged line. Cache the old III as `::vN`.

O7. Clarity runs only when this pass is complete. First sentence is the solution. Then what it is. Then why.

O8. Comments add what the raw set did not give. Prefer factoring and bridging with no comment. A comment may be factored and those factors may enter Balancing, but only if the comment is checkable general knowledge or personal data that belongs on this pass. Do not invent. Do not treat a comment as a second Right.

O9. `(p:%)` when needed and verifiable. `(~p:%)` when guessing or stating confidence.

O10. Curry with `::Name` or `"file"` plus nested `'summary'` when chaining iterations or stages. A connective by relationship or interaction must link the carried result to the next line.

Shotgun (not a phase): read or bridge at level 0 and skip Factoring only when the level-0 line already shows the sides meet. If it cannot decide, factor. Shotgun does not feed Synthesis unless you then factor. Factoring is the recommended path.

May shotgun. Raw: Maya works 17:00 through 24:00. Desk needs one person 17:00 through 24:00.

```
:Maya, available (t:1700, ..., 2400) = :Desk, covered (t:1700, ..., 2400)
```

Must factor. Raw: Maya works after 17:00. Desk needs 17:00 through 08:00.

```
:Maya, available (after (t:1700)) != :Desk, covered (t:1700, ..., 0800)
```

Section 3. Phase I: Phrasing

Write one equation from the raw set. Words on this line are level-0 factors of context. Add nothing silent.

```
Left  =  Right
```

`=` means these two descriptions are offered as equivalent. Phase III accepts or rejects that offer after both sides are defined.

Left — what is tested, offered, or already had.

- Current state  
- Inputs  
- Stacked options or potentials as perspectives  
- Candidate plan or strategy  
- Claim as stated  
- Known ends when `;` marks a missing middle  

Right — what the Left must meet.

- Goal  
- Evidence  
- Required condition  
- Constraint set  
- Required output  
- World-condition a claim is about  

Do not put the goal on both sides. Do not turn a title into the equation.

Known amounts already in the raw set belong on Phase I. Results that do not exist until Working do not. If a later factor, comment, or reason reveals a number, add it after Phase I and solve it in Working.

Optional title, not the equation:

```
:NightDesk (?)
```

Short write

Raw: Maya can work after five. The night desk needs one person from five to midnight.

```
Phase I: Phrasing
:Maya, available (after (t:1700)) = :Desk, covered (t:1700, ..., 2400), staff (1)
```

Reverse: Maya’s availability after 17:00 is offered as covering the desk from 17:00 through 24:00 with one person.

Section 4. Phase II: Factoring

Factoring is opening a level-0 factor. The factored element becomes the new Subject. Its attributes are the definition. More tokens, same meaning — definitional reduction, not new context.

True inflation is context the raw set did not give. It lives in a comment. Factor a comment only under O8.

Both sides get factored. One-sided factoring is an incomplete test.

Level 0 stays under Phase I. Level 1, 2, … are sections under Phase II.

```
Phase II: Factoring
:Maya, available (after (t:1700)), hours (7)
:Desk, covered >> staff (1) + span (t:1700, ..., 2400)
```

Reverse: Maya after 17:00 is seven hours. Desk covered requires one person across that span.

Stop factoring when the next clean line can be written. Deep factoring of every word is not required.

Section 5. Phase II?: Bridging

Use when two or more factors must be linked, or an emergent link or quality must be named. Keep the original equation on the page so the bridge has something to equal.

```
Phase II?: Bridging
:Maya, hours (7) + :Desk, span (7) -> :Cover, full
```

Reverse: Maya’s seven hours plus the desk’s seven-hour span yield full cover.

Skip when factored sides already meet.

Section 6. Phase II?: Working

Use when the sides cannot be seen to meet without an instrument.

```
Phase II?: Working
// grid: hours vs need; not required when the span already matches //
M: 2400 - 1700 = 7
```

Phase III will show `7` unless the formula is wrapped in `||...||`.

Skip when I–II already suffice.

Section 7. Phase III: Balancing

Only the clean equation plus the tag header.

```
Phase III: Balancing — Solved
:Maya, available (t:1700, ..., 2400) = :Desk, covered (t:1700, ..., 2400), staff (1)
```

Reverse: Maya from 17:00 through 24:00 equals the desk covered by one person across that span.

Tags: True, False, Unknown, Solved, Unsolved.

Section 8. Synthesis (gated)

If Phase III misses, or if it holds and a stronger Left is the goal, build a new Left from supporting factors and bridges of hits and misses. Same Right. Cache the old line. Return to Phase I.

```
Phase III: Balancing — Unsolved
:Maya, available (after (t:1700)) != :Desk, covered (t:1700, ..., 2400) + :Desk, covered (t:0000, ..., 0800)
// ::v1 night-only Maya //

Phase I: Phrasing
:Maya, night + :Dan, graveyard = :Desk, covered (t:1700, ..., 0800)
```

Stop when the new Left does not improve the tagged line.

Section 9. Phase IV: Clarity

Only when this pass is complete. Solution first. Then what. Then why.

```
Phase IV: Clarity
Maya from 17:00 through 24:00 covers the night desk as one person.
What it is: the Phase III line tagged Solved.
Why: her available span equals the required span; staff need is one.
```

If Clarity cannot say that in one sentence without hiding a second job, split.

Section 10. One pass written through

Raw: The crate must stay under forty dollars. Rope is four dollars a foot. The crate needs six feet.

```
Phase I: Phrasing
:Crate, rope (6 ft), price (||$4|| / ft) = :Cost, <= ||$40||

Phase II: Factoring
:Rope, length (6), rate (4)
:Cost, cap (40)

Phase II?: Working
M: 6 * 4 = 24
// result substituted next; formula not locked in ||...|| //

Phase III: Balancing — True
:Crate, rope, cost (24) = :Cost, <= ||$40||

Phase IV: Clarity
The crate’s rope costs 24, which is under the forty-dollar cap.
What it is: a True tagged line of cost against cap.
Why: Working multiplied given length by given rate; 24 <= 40.
```

No Synthesis. No table. Bridging not needed. That is a minimal complete pass.

Section 11. What to skip

- Bridging, when factored sides already meet.  
- Working, when no instrument would change the tagged line.  
- Synthesis, when the current Left is enough.  
- Clarity, when the pass is not complete (unfinished III going to Synthesis).  
- Extra factoring depth, when level 1 already writes Phase III.

Section 12. Curry after a finished pass

A finished tagged line may enter the next equation as input. Link it.

```
::CrateRope:(cost (24) <= ||$40||)
:Ship + ::CrateRope -> :Carton, ready
```

Reverse: CrateRope is the tagged cost line. Ship plus that tagged line becomes a ready carton.

Section 13. Short map

| Phase | Job |
|---|---|
| I Phrasing | level-0 equation; one Right |
| II Factoring | each factored element is a new Subject |
| II? Bridging | link factors; equal the original line |
| II? Working | instrument; substitute the result |
| III Balancing | clean `=` or `!=` plus tag header |
| Synthesis? | new Left, same Right, cache, return to I |
| IV Clarity | solution, what, why |

FaCD 01.01 — Module 4: Rosetta

A raw block becomes notation. The notation becomes speech again. If that loop is not reliable, the flow will argue about words instead of sides.

This module drills that loop. It does not run Factoring through Clarity. A setup line may appear so the raw block has a Left and a Right.

When you later run a problem, you read and solve in expression notation. You reverse-translate the solution. In this module you reverse the whole phrase so the loop can be checked.

Section 1. Default compression

Default sits in the middle: filler dropped, sacred content kept, stack and nest without squeezing unrelated facts onto one stem.

- Looser: nearer to prose, same symbols, when fidelity is easier to see that way.
- Denser: same facts, shared relationships written once, when compression is the point.
- Style is preference. If the rules are kept, every style reverse-translates to the same original data points. Filler words return from context when reading. Sacred content never depends on that guess.
- `||...||` never changes.

Sacred content: subjects, attributes, interactions, decisions, reasoning, relationships, conditionals, dependencies, outcomes.

Fidelity first. Length second. Styles of phrasing raw data into expression notation are flexible, though all rules must be followed with all data represented for the sake of intuitive coherence and fidelity. A reverse that drops a decision or invents a reason has failed.

Filler is connective tissue a fluent reverse can supply. It is not license to drop a ranking, a cap, a reason, a conditional, a dependency, or a file.

Section 2. How to phrase a raw block

1. Mark subjects, decisions, reasons, conditionals, dependencies, times, amounts, files. Those become level 0.
2. Drop only filler.
3. Stack while Readable Flow holds.
4. Use `H` when order was actually ranked, or when non-shared slots must stay paired.
5. Lock exact caps and quotes in `||...||`.
6. Point outside with `"file"` and nest `'summary'` immediately under it.
7. If the raw set is a problem, write one equation: Left = Right. A title is not the equation.
8. Reverse out loud. Missing raw decision → put it back. Invented cause → drop or `// comment //`.

Section 3. Statement

Raw
The café opens at 7 and Alice cannot work evenings.

Standard (default)

```
:Cafe, opens (t:0700), :Alice, !work (evening)
```

Reverse
The café opens at 7. Alice does not work evening.

Looser

```
:Cafe, opens (time (7am)), :Alice, cannot (work (evening shift))
```

Denser

```
:Cafe, (t:0700) + :Alice, !work (evening)
```

All three reverse to the same two facts. A reverse that adds “Alice prefers morning” failed: that factor was not in the raw set. `!evening` alone would drop the verb the raw set gave: work.

Section 4. Plan as equation

Raw
We have a prototype. We need a shipped product.

```
:Project, prototype = :Project, shipped
```

Reverse
The project is at prototype. That state is offered as equal to shipped.

Left is current state. Right is the goal. Do not factor `shipped` into stages on this line unless the raw text already ranked them.

Section 5. Full paragraph — two styles, one raw

Raw
The shop team spent Tuesday arguing how to detect wind on a field box that has to stay under forty dollars. Alice wanted a printed vane on a hall sensor because they already have filament and a spare magnet. Bob wanted an ultrasonic pair because rain wrecks moving parts. They ranked the printed vane first and ultrasonic second. If the vane warps in heat, they switch to ultrasonic and reopen the enclosure size. No field test until a bench calibration exists. Calibration needs the wind tunnel slot booked after the enclosure is printed or bought. Notes live in "wind_box_tuesday.md".

Phrasing A

```
:Shop team, (t:Tuesday), wind detect, box, cost < ||$40||
H:(1: printed vane + hall sensor, 2: ultrasonic pair)
:Alice, reason (filament + spare magnet already on hand)
:Bob, reason (rain wrecks moving parts)
:Vane, warps (heat) -> ultrasonic + reopen enclosure size
:Field test >> bench calibration >> wind tunnel slot >> enclosure (printed | bought)
```

Section 8. How to check a reverse

Read the raw block. Read the reverse. Ask:

- Is every subject still there?
- Is every decision, reason, conditional, dependency, time, amount, and file still there?
- Did a new cause appear?
- Did `||...||` get paraphrased into “cheap” or “soon”?
- Was an attribute written as if it were `is` / `=`?
- Was a verb from the raw set dropped (`work` in “cannot work evenings”)?

If a new cause appeared or an invariant was paraphrased, the phrasing failed. Rewrite the notation, not the raw set.

All original data points must be recoverable. Filler may be supplied from context when reading. When a problem is solved later, reverse-translate the solution, not every working line.

Section 9. Common misreads

- Title taken as the equation.
- Research or preference stuffed into the phrase.
- `(p:%)` stamped on ignorance.
- `;` used for a missing end instead of a missing transform.
- A reverse that adds context.
- Letter-substitution without a legend on the page.
- `"file"` written without a nested `'summary'` when the reader will not open the file.
- Negation written on the wrong word (`!evening` when the raw set negated work).

Letter-substitution is not taught. A private legend, if used, must sit as `// comment //`.

FaCD 01.01 — Module 5: Setup gallery

A setup is how Left and Right are paired for a job. Any Left type may meet any Right type when that pairing is the actual job. World and evidence may serve the same role. Plan and options may serve the same role. The names below are common pairings, not a closed law.

This module writes the equation. It does not run Factoring through Clarity.

Section 1. By need

The equation follows what the session is doing. Mix two needs when the raw set actually mixes them. Do not invent a second Right to hold a second need.

| Need | Common pairing | Extra phases |
|---|---|---|
| Uncover meaning from a limited set | `Left = ?`, then factors onto the Right | Factoring. Inverse if more detail is wanted. |
| Learn what a term is, no test | `:Term = ?`, then `:Term =` factors | Factoring. Cache `::Name` if a later pass will use it. |
| Discern truth | Claim vs world, or testimony vs evidence | Factor both sides. Bridging if a link must be named. |
| Solve a problem | Plan vs goal | Factor. Working if numbers require it. |
| Pick among options | Stacked options vs one goal | Factor the stack. Synthesis if a new option is the point. |
| Break a goal into steps | Staged goal | `H` or `+` on the Right. Curry each stage. |
| Synthesize a new option | Same pairing as the first pass | Synthesis. Needs factored sides. |
| Integrate a concept with math | Math already on Phase I | Working. Phase III shows the result unless `||formula||`. |
| Test options vs constraints | Stacked Left vs one constraint-Right | Factor. Working for totals. |
| Find a missing transform | Lambda (`Input ; Output`) | Factor both ends. Bridge the middle. |
| Carry a known now into a desired later | `:Was -> :Is ; :Should` | Factor Is and Should. Bridge the hole. |
| Find a missing end | `-> ?` or `? ->`, not `;` | Factor what you have. |

Wrong pairing (same raw, bad write)

| Raw need | Wrong write | Why wrong |
|---|---|---|
| Learn what steam is | `:Heat ; :Steam` | That is lambda. Use `:Steam = ?`. |
| Hole between two known ends | `:Steam = ?` | That is research. Use `;`. |
| Known now, desired later | `:Now ; :Should` | The known flow was dropped. Use `:Was -> :Is ; :Should`. |
| Two jobs (roster and print) | one equation, two Rights | Split. |
| Title of a puzzle | `:Cafe (?)` with no `=` | Title is not the equation. |
| Missing end | `:Heat ; ?` | `;` needs two known ends. Use `:Heat -> ?`. |

Name the need in a comment under Phase I when the pairing would otherwise be ambiguous.

```
// need: uncover context, not a truth test //
```

Section 2. What the two sides are doing

A semantic equation is a truth statement. `2 + 2` defines `4`. The Left defines, explains, or satisfies the Right.

| Left | Right | Common name |
|---|---|---|
| A claim about a thing | The condition that would make the claim hold | Claim vs world |
| Current state or candidate plan | The goal | Plan vs goal |
| Current state | A goal that splits into stages | Staged goal |
| Several options or potentials | The shared condition they must meet | Stacked options |
| Witness reports | A record or measurement | Testimony vs evidence |
| One ratio | The other ratio | Proportion |
| Two known ends (`Input ; Output`) | The named transform | Lambda |
| Known past-to-present, desired future still a hole | The named transform present-to-desired | Predictive |
| A named quantity | The formula that defines it | Math-in-line |
| A stack of strategies | The scoring goal of the meet | Tournament |
| The complementary form of a claim | The condition that form explains | Inverse |
| A statement with no test yet | `?` until factors move onto the Right | Open information |
| A term you want defined, no test | The factors of that term | Research |
| A trigger or branch | The next action | Code / flowchart |

One equation has one Right. Stack two or more options on the Left when they share that Right — encouraged, not required.

If the raw set names two goals, write two equations or stage them. Stacking several Rights in one equation is taught with methods.

Minimal path: if one pair already writes a readable `Left = Right`, stop.

Section 3. Stack the options

One option at a time is allowed (`:OptionA = :Goal`, then later `:OptionB = :Goal`).

When more than one claim, view, or candidate could explain the same Right, stack them on the Left and test that collection in one equation.

```
:OptionA, :OptionB, :OptionC = :Goal
```

Factor both sides. Balancing can flag a miss, mark a hit, and keep supporting factors from both for Synthesis. Failed options stay useful. Missing pieces from the factored Right stay useful.

Split when the Rights are different jobs.

Section 4. Claim vs world

Left explains a world-condition on the Right. Later tag: True | False | Unknown.

Raw
Water boils at 100C at standard pressure.

```
:Water, boils = :Temperature, 100C + :Pressure, standard
```

Reverse
Water boils when the temperature is 100C and the pressure is standard.

Section 5. Plan vs goal

Left (state or plan) must satisfy the goal on the Right. Later tag: Solved | Unsolved | Unknown.

Raw
We have a prototype. We need a shipped product.

```
:Project, prototype = :Project, shipped
```

Reverse
The project is at prototype. That state is offered as equal to shipped.

Section 6. Staged goal

Same pairing as plan vs goal when the goal cannot finish in one Balancing. Factor the Right into subgoals. Ordered: `H`. Parallel: `+`. Each stage is a later pass. Curry the tagged line forward.

Raw
We have a prototype. Shipped means lock design, then test, then release.

```
:Project, prototype = :Project, shipped
:Shipped, H(1: design locked, 2: test, 3: release)
```

Reverse
The project is at prototype. Shipped means design locked, then test, then release.

Do not run all three stages here. The setup is the split.

Section 7. Stacked options

Raw
Alice wants morning. Bob wants afternoon. Charlie wants evening. One person per shift.

```
:Alice, prefers (morning), :Bob, prefers (afternoon), :Charlie, prefers (evening) = :Constraint, one person per shift + one shift per person
```

Dense Left when pairing is real:

```
H:(1:Alice, 2:Bob, 3:Charlie), prefers (1:morning, 2:afternoon, 3:evening) = :Constraint, one person per shift + one shift per person
```

Reverse
Alice prefers morning, Bob afternoon, Charlie evening. That stack is set equal to one person per shift and one shift per person.

A title `:Cafe (?)` is not this equation.

Section 8. Testimony vs evidence

Left (reports) is offered as the explanation of Right (the record). Do not treat a witness as a camera.

Raw
Two witnesses say the door was locked. The camera shows it open at 9.

```
:Witness1, door (locked), :Witness2, door (locked) = :Camera, door (open), (t:0900)
```

Reverse
Witness one and witness two say the door was locked. That is set equal to the camera showing the door open at 9.

The miss is a later Balancing. This module only writes the pairing.

Section 9. Proportion

One ratio set equal to another. Keep the same order of parts.

Raw
If 2 workers finish a wall in 6 hours, 4 workers should finish it in 3.

```
:Workers (2) / :Hours (6) = :Workers (4) / :Hours (3)
```

Reverse
Two workers in six hours is offered as equivalent to four workers in three hours.

Working may later test the numbers. The setup is the proportion.

Section 10. Lambda

`;` marks a missing transform only. Both ends are known. The hole is the middle.

Raw
Heat goes in. Steam comes out. What happened in between?

```
:Heat ; :Steam = ?
```

Reverse
Heat transforms into steam by an unnamed process.

Known transform, unknown output — not `;`:

```
:Heat -> ?
```

Known transform, unknown input — not `;`:

```
? -> :Steam
:Steam = ?
```

Factoring both ends is how the middle gets named. That solve is taught with methods. The setup here is the semicolon between two known ends.

Section 11. Predictive

Known flow into the present, desired future still a hole.

```
:Was -> :Is ; :Should = ?
:(A + B) -> :C ; :D = ?
```

Reverse
What was became what is; how what is becomes what should be is not yet named.

If a cap was in the raw set, it sits on the same Right. Do not add a second equation unless the cap is a second job.

Section 12. Research and open information

Research — define a term, no world-test:

```
:Steam = ?
:Steam = (:Water + :Heat) ->> :Gas, phase (change)
```

Open information — a statement or question with no test yet. Factors move onto the Right.

```
:Latch, engaged = ?
```

`:Steam = ?` and `:Heat ; :Steam` are different jobs. Do not swap them.

Section 13. Math-in-line

A raw amount or formula already said belongs on Phase I.

```
:Crate, rope (6 ft), price (||$4|| / ft) = :Cost, <= ||$40||
```

Working multiplies later. The setup already holds the given numbers.

Section 14. Tournament

A stack of strategies versus a scoring goal.

```
:AlwaysC, :AlwaysD, :TFT, :Random = :Score, maximized across opponents
```

Simulation lives in Working. The setup is the stack against one scoring Right.

Section 15. Inverse

The complementary form of a claim, offered as equal to a condition that form explains.

```
:Sky = :Blue, (t:day)
:Sky != :Blue, (t:night)
```

Both may be true. Inverse is a new Phase I, not a left arrow.

Section 16. Code / flowchart

A trigger or branch as the next action.

```
:File, exists -> :Open >< :Create
```

Reverse
If the file exists, open it; else create it.

Section 17. Two jobs

Roster and print are two Rights. Write two equations. Cache and link if they share people or dates.

```
:Alice, :Bob, :Cara = :Tuesday, covered
:Print, Maya (Wednesday morning) = :Date, Friday
```

Do not smash them into one tagged line.

Section 18. Short map

| Pairing | Write |
|---|---|
| Claim vs world | claim = condition |
| Plan vs goal | state or plan = goal |
| Staged goal | plan = `H` or `+` of stages |
| Stacked options | options = one Right |
| Testimony vs evidence | reports = record |
| Proportion | ratio = ratio |
| Lambda | `:In ; :Out = ?` |
| Predictive | `:Was -> :Is ; :Should = ?` |
| Research | `:Term = ?` |
| Missing end | `-> ?` or `? ->` |
| Math-in-line | given amounts on Phase I |
| Tournament | strategies = scoring goal |
| Inverse | complement = its condition |
| Code | trigger `->` action `><` else |

FaCD 01.01 — Module 6: Worked problems

Section 0. How to read these

One need, one Right, one pass. A Solved pass may still open another pass when a stronger Left is the point. Clarity always starts with the solution, then what it is, then why.

Advice

- Stack known, hypothetical, and random options on the Left when they share one Right.  
- A first legal tagged line can be Clarity plus `::vN`, then one option in the next Phase I.  
- Working may simulate games or hunts. Report wins out of games played, or moves out of hunts run. Phase III uses those counts, not the raw grid.  
- Name a reusable rule as `::Name` so a later pass can substitute it.  
- Spell strategy names in full on first use. `::AlwaysDefect` is Always Defect, not “D.”  
- Use `!=` for a miss. Do not write a slashed equals. Do not use a hyphen to mean remove.  
- Recommend reiteration in Clarity when a better set of factors was not used yet.  
- Tables are not required. Use one when listing, striking, or scoring is easier to see than a stack. Skip the table when Factoring and Bridging already name the tagged line.

Map by Need

|---|---|
| 1 Staffing | Assign under constraints |
| 2 Robbery | Testimony vs evidence |
| 3 Conference | Plan vs date, demo, budget, people |
| 4 Treasure | Hunt rule vs find plus few moves |
| 5 PD | P1 rule vs max wins in a pool |

Problem 4. Treasure hunt

Why this example is here
A hunt has several complete rules, not a vibe. Write each rule so a person or a program can follow it with no extra judgment. Simulation is rare Working. Put the counts in comments. Factor the comments. Synthesis reads those factors. A table is not required and is not the answer.

Raw
10 by 10 grid. After each move: Hotter, Colder, or Same by Manhattan distance. Legal steps: N S E W and the four diagonals. Start unknown. Treasure unknown.

Shared bookkeeping

```
::Possible:(every cell at start)
:AfterClue, drop any cell that could not have made that clue
M:d = |x_t - x| + |y_t - y|
// x_t, y_t treasure cell; x, y hunter cell //
:Hotter, M(d_new < d_old)
:Colder, M(d_new > d_old)
:Same, M(d_new = d_old)
:Center, mean of cells still in ::Possible
```

First heading is not a silent roll. Heading rules share this start:

```
::TowardCenter:(step one cell toward :Center; if both axes still differ, take the diagonal that reduces both; if only one axis differs, take that cardinal)
```

Named rules

```
::RandomWalk:(each turn pick any legal neighbor by a fair roll, ignore the clue)
::AxisScan:(from the start cell walk east to the wall, one step south, walk west to the wall, one step south, repeat; ignore the clue)
::HotAxis:(first step ::TowardCenter using cardinal only; then keep that cardinal heading on Hotter; reverse it on Colder; on Same turn 90 degrees clockwise from the current heading)
::BisectHotter:(first step ::TowardCenter; then keep that heading on Hotter; reverse it on Colder; if the reverse cell is off the grid, take the cardinal part of that heading instead)
::MinRemain:(each turn list every legal neighbor; for neighbor N count how many ::Possible cells remain if the clue is Hotter, and again if Colder; score(N) = the larger of those two counts; play the N with the smallest score; if two scores tie, play the neighbor closer to :Center)
```

How to run ::MinRemain
1. List neighbors on the grid.  
2. For each neighbor, count leftover ::Possible if Hotter, and if Colder.  
3. Score = the larger count.  
4. Play the smallest score. Tie → closer to :Center.

No heading memory. No hidden roll after the first list exists.

Phase I: Phrasing

```
::RandomWalk, ::AxisScan, ::HotAxis, ::BisectHotter, ::MinRemain = :Hunter, cell (treasure) + :Moves, few
```

Phase II: Factoring — Level 1

```
::RandomWalk, uses clue (no)
::AxisScan, uses clue (no)
::HotAxis, uses clue (yes), neighbors (4), memory (heading)
::BisectHotter, uses clue (yes), neighbors (one heading)
::MinRemain, uses clue (yes), neighbors (all legal), score (worst leftover)
```

Phase II?: Working
Rare case. Run the five written procedures. Write counts as comments so they can be factored. Do not treat a grid as Phase III.

```
// sim: 20 hunts each rule, random start and treasure, stop when hunter cell = treasure cell //
// ::RandomWalk, median 41, finished in 15 = 2 of 20 //
// ::AxisScan, median 50, finished in 15 = 0 of 20 //
// ::HotAxis, median 16, finished in 15 = 9 of 20 //
// ::BisectHotter, median 12, finished in 15 = 16 of 20 //
// ::MinRemain, median 9, finished in 15 = 19 of 20 //
```

One shared hunt. Start (5,5). Treasure (2,9). Grid center is about (5.5,5.5), so ::TowardCenter walks to (6,6), away from T. Distance at start: M:|2-5|+|9-5| = 7. Step (6,6) keeps d = 7 (Same). A planted walk into the middle cannot be the winner here.

| Rule | Moves to T | Clues in order | First step |
|---|---|---|---|
| ::RandomWalk | 22 | ignored | roll |

Problem 5. Prisoner’s dilemma

Raw
Each round Cooperate or Defect. A match is 10 rounds. Payoffs locked: (C,C)=(3,3), (C,D)=(0,5), (D,C)=(5,0), (D,D)=(1,1). Pool: Always Cooperate, Always Defect, Tit For Tat, Grim, Win Stay Lose Shift, Random. P1 wants the most match wins against that pool.

| Always Cooperate | draw | loss | draw | draw | draw | varies | 0 of 5 |
| Always Defect | win | draw | win | win | win | varies | 4 of 5 |
| Tit For Tat | draw | loss | draw | draw | draw | varies | 0 of 5 |
| Grim | draw | loss | draw | draw | draw | varies | 0 of 5 |
| Win Stay Lose Shift | draw | loss | draw | draw | draw | varies | 0 of 5 |

Always Defect wins 4 of 5 deterministic matches because a draw vs itself and a win vs every C-starter. Tit For Tat does not beat Always Cooperate (both score 30). vs Random is not a single cell: Random has no rule, so that seat is not counted in the 5. That is the static table, not the final Left.

Phase IV: Clarity — pass A

Solution so far: Always Defect wins 4 of 5 deterministic matches and still loses the *character* of the nice seats (it never earns a draw-as-friends; it milks Always Cooperate). Tit For Tat, Grim, and Win Stay Lose Shift draw those nice seats and lose to Always Defect.  
Reiteration: Synthesize a rule that draws or wins the nice seats *and* wins Always Cooperate.

Pass B — Synthesis

```

// static five ::v1 //
```

Working — pass B, same five seats plus the Always Cooperate exploitation check

| P1 rule | vs AlwaysCooperate | vs AlwaysDefect | vs TitForTat | vs Grim | vs WinStayLoseShift | vs Random | Wins of 5 deterministic |
|---|---|---|---|---|---|---|---|
| SenseShift | win | loss | draw | draw | draw | varies | 1 of 5 plus three draws |

SenseShift vs Always Cooperate: three C, one probe D, then Always Defect for the rest. P1 sum 44, P2 sum 18. P1 wins that match. Vs Tit For Tat: probe is punished, return to Tit For Tat, draw.

```
// Working: vs Random, each round C or D by a fair coin; 20 matches of 10 rounds; not one deterministic cell //
// ::Random, vs SenseShift, result varies across those 20; no single win loss to add to the 5 //

```

Solution: P1 plays `::SenseShift`. Start as Tit For Tat. After three unanswered Cooperates, Defect once. If the opponent punishes, return to Tit For Tat. If the opponent stays Cooperate, switch to Always Defect.  
What it is: a named substitutive for later passes. It wins the Always Cooperate match that Tit For Tat only draws, and it still draws Tit For Tat, Grim, and Win Stay Lose Shift.  
Why: pass A showed Always Defect taking 4 of 5 by milking nice rules, and Tit For Tat taking 0 of 5 because draws are not wins. SenseShift keeps the nice draws and converts Always Cooperate into a win. Random remains a pool member with no single win loss cell, so it is not counted in the 5.  
Reiteration: if the pool forbids a probe, `::TitForTat` is the tagged line again.

Section 2. Lambda — two solved passes

```
? -> :Steam               // unknown input, not lambda
:Heat ; :Steam = ?        // lambda (energy in, state out)
:Water ; :Steam = ?       // lambda (substance in, substance out)
```

Raw
Heat goes in. Steam comes out. What happened in between?

```
:Steam, water (gas)

Phase II?: Bridging

:Water, gas = :Steam

What it is: heat is the input energy; steam is the output state. Water was uncovered by factoring Steam (and by ::SteamDef if that research pass already ran).
```

Section 4. Left = ? then factors become the staged Right

Use this when the raw set names a large goal and does not already name the stages.

Not only products. A diagnosis protocol is the same write:

```
:Case, closed = ?
:Case, closed = H(1: history, 2: exam, 3: test, 4: call)
```

Each `Hn` is its own pass. Curry `::History` into exam. The join is still `:Case, closed = H(::History, ::Exam, ::Test, ::Call)`.

Factors of a word can be two different things:

- Definition only: they explain the word. They may not be work stages.
- Stages: they are work that must happen, in order or in parallel.

If they are only a definition, stop at the information tagged line. If they are work, write `H` or `+` and solve each stage.

Raw

That line is the large equation. It is not yet Solved. Each Hn is its own pass with one Right.

```

```

Each side of `+` is still its own pass. The join Clarity uses `+` instead of `H`.

Section 7. Why Special Sets and cache belong here

| Tool | Job in this method |
|---|---|
| `::StageN:(...)` | Name a finished stage so the next pass can point at it |
| `::vN` | Keep a beaten stage-Left readable |
| `"file"` + `'summary'` | Curry a stage that is not in-line |
| `H` | Order on the large Right |
| `+` | Parallel stages when order does not matter |

Without names, Stage 3 copies Stage 1 and re-argues freeze now. Without `::vN`, you cannot see what Synthesis dropped.

Section 8. Tips

- Prefer same-kind ends on `;`. Energy versus a substance is usually a bad pair.
- Factors of the transform sit on the bridge or as `requires (...)`, not as a second Right.
- Do not invent the middle. If factors cannot name it, tag Unknown and say what hole remains.
- One Balancing tag cannot bless two jobs. Split, cache, link.
- When a cached tagged line blocks the next job, change one Right on purpose. Do not silently edit the cache.
- `Left = ?` is temporary. If the factors are work, they become `H` or `+`. If they are only a definition, stop.
- Name every Solved stage before the join Clarity.
- Default reverse uses in-line, not the cache.

Section 9. Checklist

- Pairing named.
- One Right per equation.
- `;` only for a missing middle. Ends are the things transformed.
- Two jobs: two passes plus a join note, not one tag.
- `Left = ?` only until factors can sit on the Right.
- Each stage Solved and named before the join Clarity.
- Unused stronger factors went into Synthesis or a named later pass.

- Predictive lambda + constrained forecast  
- Cross-domain + split Rights if the link is a second job  
- Tournament + parallel instruments + Sense-gate + Synthesis  
- Failure autopsy + inverse + new plan vs goal  
- Proof chain + hybrid mode  
- Layered model + iterated rule on one layer  
- State table + conflict balance (rows are the camps)  
- Reverse-engineer flowchart + Sense-gate function + code block test  
- Staged goal + layered system + described media (the flow picture)  
- Alibi reconciliation + testimony vs evidence + ranked record (`::RankedRecord` into the next story)  
- Differential elimination + `::Possible` shrinking + failure autopsy on the last miss  
- Dimensional check + hybrid mode before any magnitude Working  
- Invariant-preservation + staged goal (`||must-hold||` on every stage)  
- Task-adapt: reverse-engineer stages + domain skill per stage, not on the whole Right  
- Sim-as-Right + tournament or hunt (run first; measured output becomes the next Right)  
- Alibi reconciliation + differential elimination (stories ranked, then causes struck against the same record)  
- Dimensional check + proof chain (units on each lemma before the join)  
- Invariant-preservation + sim-as-Right (runs that break `||...||` never become the new Right)  
- Task-adapt + layered model (imported knowledge lands on one layer only)

Inventing a mix is allowed. Inventing a glyph is not. Do not flatten three tags into one line.

Section 25. Checklist

- Technique named in a comment.  
- One Right unless a split already ran.  
- Each named move has a write and a pass, not a slogan.  
- Curry with `::Name`.  
- `(p:%)` only when real.  
- Clarity leads with this pass’s solution.

FaCD 01.01 — Module 10: How to choose and combine

Module 5 tells you the pairing. Module 9 teaches each advanced move. This module is which write, when to add a second move, and how to test a mix without flattening tags.

You still write one equation and one Right per pass. A synergy is several passes (or several Working instruments) with curry, not one magic line.

Section 1. First question

What is the raw set trying to do?

| If the raw set is doing this | Write this first | Where taught |
|---|---|---|
| Learn a word | Research `:Term = ?` | 5 |
| Two known ends, hole in the middle | Lambda `:In ; :Out = ?` | 5, 7 |
| Known now, desired later | Predictive `:Was -> :Is ; :Should` | 5, 9 |
| Known now + a named cap on that future | Constrained forecast | 9 |
| Is this true of the world | Claim vs world | 5 |
| Stories vs a record | Testimony vs evidence | 5, 6 |
| Plan vs a goal | Plan vs goal | 5, 6 |
| Large name, no stages yet | `:G = ?` then `H` or `+` | 7 |
| Several options, one demand | Stack on the Left | 5, 6 |
| Rules vs a score | Tournament | 5, 6 |
| Two jobs | Split Rights | 7 |
| Inherited machine, no map | Reverse-engineer | 9 |
| Field knowledge must enter | Domain skill (`"source"` + test) | 9 |
| Stories clash before either meets the record | Alibi reconciliation | 9 |
| Candidate causes vs what is observed | Differential elimination | 9 |
| A formula or magnitude before units | Dimensional check first | 9 |
| Variants vs what must not move | Invariant-preservation | 9 |
| Old training on a new task shape | Task-adapt | 9 |
| A run must mint the next Right | Sim-as-Right | 9 |
| Missing end only | `:In -> ?` or `:Term = ?` — not `;` | 5 |

If two rows both fit, you have two jobs. Split.

Section 2. Second question — do you need an advanced move?

Stay on the basic pairing until one of these is true.

| Symptom | Add |
|---|---|
| Level 0 already decides | Shotgun (Module 3). Stop. |
| First III misses and the opposite would uncover data | Inverse (Module 5) |
| Two camps, one Right | Conflict balance |
| Tag is False or Unsolved and you must name why | Failure autopsy |
| A pattern should change the next write | Sense-gate |
| A word will be re-argued for three stages | Definition lock |
| One score would lie | Parallel instruments |
| Two fields share the demand | Cross-domain bridge |
| Need a picture, path, clip, matrix, tensor | Described media / sim |
| Discrete plus a formula | Hybrid mode |
| Many agents or rounds as rows | State table |
| Prove in lemmas | Proof chain |
| Pipeline / org / net | Layered model |
| Repeat a named block | Iterated rule |
| A real rate is in the raw set | Stochastic Working |
| Must ship a named function | Sense-gate as `::Fn` |
| Must rebuild after tear down | Reverse-engineer then layered / staged |
| Stories contradict each other before the record | Alibi reconciliation |
| Causes must be struck, not scored as best | Differential elimination |
| Units might not match | Dimensional check before hybrid Working |
| A cap or postulate must survive every variant | Invariant-preservation |
| Prior notes would otherwise dump on the whole Right | Task-adapt |
| The constraint is a measured run, not a given Right | Sim-as-Right |

If none of these fire, do not open Module 9.

Section 3. Third question — mix or stay

A mix is legal when the second move takes a named result from the first as input.

Illegal mix: two Rights, one tag.  
Legal mix: `::SteamDef` then `:Water ; :Steam`, then predictive on that named transform.

Order that usually works

1. Research / reverse-engineer (know the words or the as found flow).  
2. Lock the definition if the word will travel.  
3. Basic pairing (lambda, claim, plan, tournament, staged).  
4. Advanced add-on only if a symptom from §2 is present.  
5. Working instruments (media, table, code block, M). Dimensional check before magnitude.  
6. Synthesis or Sense-gate if III misses or a sensor fires.  
7. Join Clarity only after each stage has a tag.  
Sim-as-Right sits before the next Phase I: the run is Working, the measured constraint is the new Right. Task-adapt puts domain imports on one stage only. Invariants ride every stage that claims to meet them.

Parallel techniques: two Working comments on one pass. Parallel setups: two equations, not one line.

Section 4. Complex test pattern

When the session must test a system, not only name it:

```
Reverse-engineer or layered model   -> named ::System
Sense-gate functions on a layer     -> ::Fn
Code block or sim Working           -> comments
Factor comments                     -> III tag on ::Fn or ::System
Failure autopsy if a call misses
Iterated rule if many inputs
Described media if the flow must be seen
```

Each box is its own tag unless it is only Working under one Phase I.

```
::DoorMap:(fob -> valid -> open)
::OpenIfValid:(:Fob, valid -> :Open >< :Stay)
// Working: code block, four fobs //
:Calls, four = :OpenIfValid, meets
```

If one fob is illegal, autopsy that call. Do not retcon `::DoorMap`.

Section 5. Synergy recipes

Use these as starting mixes. Change them when the raw set changes.

A. Know then transform — research + definition lock + lambda.  
B. Now into desired under a cap — predictive + constrained forecast.  
C. Two fields, maybe two jobs — cross-domain first; split if one tag cannot tell the truth.  
D. Contest — tournament + parallel instruments + Sense-gate + Synthesis.  
E. Almost-worked plan — failure autopsy + inverse + new plan vs goal.  
F. Proof — proof chain + hybrid mode (`||M(...)||` in a lemma).  
G. Architecture — layered model + staged goal + iterated rule on one layer.  
H. Inherited box — reverse-engineer + flowchart Working + Sense-gate `::Fn` + code block test + layered rebuild.  
I. Noisy line — stochastic Working only with a real rate + constrained forecast if a cap exists.  
J. Picture of a rule — described media + the rule’s pairing (hunt, PD, door map).
K. Stories vs record, ranked — alibi reconciliation + testimony vs evidence; curry `::RankedRecord`.  
L. Causes vs observed — differential elimination + `::Possible` shrinking; autopsy the last miss.  
M. Number first — dimensional check then hybrid; units False stops magnitude.  
N. What must not move — invariant-preservation + staged goal; every stage carries `||...||`.  
O. Old knowledge, new shape — task-adapt: reverse-engineer stages, domain skill per stage.  
P. Measure then constrain — sim-as-Right + tournament or hunt; the run mints the next Right.  
Q. Ranked stories then struck causes — alibi reconciliation + differential elimination on one record.  
R. Units on each lemma — dimensional check + proof chain before the join.  
S. Runs that break a lock die — invariant-preservation + sim-as-Right.  
T. Import lands on one layer — task-adapt + layered model.

Section 6. Anti-patterns

- Opening Module 9 because the list is long.
- `;` on a missing end.
- Predictive when you only wanted research on `:Should`.
- Two scores silently averaged instead of Parallel instruments.
- Ethic or budget invented onto the Right.
- Flattening H, I, J into one equation.
- Reopening a locked definition because a later stage is bored.
- Decorative `(p:90%)`.
- Treating a flowchart picture as Phase III.
- Testing a `::Fn` by rewriting it instead of a code block Working.
- Dumping a textbook onto the whole Right instead of task-adapt per stage.
- Scoring a “best cause” when the raw set only supports striking (`::Possible - A`).
- Letting a sim that broke `||...||` become the next Right.

Section 7. Pairing list

Claim vs world. Plan vs goal. Staged goal. Stacked options. Testimony vs evidence. Proportion. Lambda. Predictive. Unknown output. Unknown input. Research. Inverse. Math-in-line. Tournament. Code / branch. Split Rights. Join after stages. Curry. Title (not a setup).

Advanced moves: Module 9 roster including reverse-engineer, domain skill, alibi reconciliation, differential elimination, dimensional check, invariant-preservation, task-adapt, and sim-as-Right.

Section 8. Walk a messy raw set

Raw
“We have last year’s door. It unlatches somehow. We want a logged open. Budget $200. Legal wants two person night if we add heat.”

That is at least three jobs. Do not one-line it.

Pass A — tear down  
Reverse-engineer `:Door = ?` → `::DoorMap`.

Pass B — function  
Sense-gate `::OpenIfValid`. Code block test.

Pass C — desired future  
Predictive: `:Unlatches -> :Now ; :LoggedOpen`. Constrained if $200 is on this job.

Pass D — heat vs labor  
If heat and two person night share one survival Right, cross-domain. If legal hours are a second boss, split.

Join note, not a fifth Right:

```
::DoorMap + ::OpenIfValid + ::LoggedOpen + ::NightRule
```

Section 9. Scientific messy set

Raw
“Energy inequality is in the notes. We want regularity. Cap: no new postulate. Lemma 1 might be bounded energy. Lemma 2 might be compactness. A chat draft said smooth. We do not trust that.”

Pass A — research + definition lock  
`:Regularity = ?` → `::RegLock`.

Pass B — domain  
`"energy-notes.md"` as a candidate lemma, not a tag.

Pass C — proof chain  
`:Claim, regular = H(1: ::EnergyBound, 2: ::Compactness)`.

Pass D — conflict  
Chat draft without factors `!= ::RegLock`.

Join is program status, not “the problem is solved.”

Section 10. Done

You picked well when:

- The first pairing matches §1.
- Each advanced move matches a §2 symptom.
- Each pass has one Right and a tag.
- Tests live in Working or in a following pass.
- Clarity of the last pass can name the whole mix in one sentence without hiding a second job.

If it cannot, you still have a split to do.
